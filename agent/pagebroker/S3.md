# S3 storage contract

The S3 backend handles storage operations through the AWS SDK, and Model
Streamer restores payloads through its native S3 plugin.

## Payload uploads and native restores

`S3StorageBackend::UploadCheckpoint` accepts an immutable source directory and
an explicit, exclusively owned bucket/key for every regular file, including
empty files. It validates the complete inventory, paths, destinations and sizes
before writing any payload. Files within a tree upload sequentially through
the AWS SDK; multipart requests and concurrent calls share the backend's
lazily created `S3Client` and its resource limits.

The result is a `RestorePlan` containing S3 locators, sizes, SHA-256 digests,
file/directory permissions and empty directories. Payload upload alone does not
publish a checkpoint index. Callers keep the source immutable and the backend
alive until their calls finish, and own destination keys and partial-upload
reconciliation.

`ModelStreamerRestore::Stage` reads payloads through the native S3 plugin.
Digests are checked after native access finishes and before final permissions
are applied. Expected digests are optional in externally supplied restore
plans; every file in a backend-produced upload plan has one. The application
SHA-256 is independent of transport checksums and ETags.

Native sessions admit at most eight submissions with a combined 10 GB target;
an oversized file occupies a session alone. Admission closes when the first
submission completes. All destinations remain mapped until the session ends,
even after successful responses. The target bounds native session retention,
not total staging memory, which also includes queued restore mappings.

The pinned plugin cancels and removes S3 clients process-wide on session
teardown. A process-wide admission guard prevents separate coordinators from
overlapping native session lifetimes. Reads in the admitted session still run
concurrently; waiting coordinators continue checking cancellation and deadlines.

The engine replaces a failed restore coordinator using the same connection
settings and restore timeout. Each native session receives those credentials
before its first request. The pinned API has no per-submission cancellation or
live credential replacement. Cancelling an accepted restore stops the shared
session and can fail concurrent restores; cancelling queued work leaves active
reads running. In either case, callers return only after native access to their
buffers has stopped.

Empty files are created locally without a native download. Callers preparing
raw restore plans must separately check remote empty-object existence. Source
keys are passed literally to the pinned URI parser, without percent-encoding;
keys containing newline characters are unsupported. S3 URIs must not be put
into filesystem protobuf fields.

## SDK client and failure handling

`transfer/s3/s3_client.hpp` provides file uploads, object HEAD, bounded metadata
GET and conditional metadata PUT. SDK initialization and shutdown are internal.
Metadata calls share connection settings and request limits without allocating
upload buffers. Checkpoint validation and publication policy belong to
`S3StorageBackend`; the client provides the underlying object operations.

`S3Client::UploadFile` hashes and uploads through the same open file descriptor
and returns the size and SHA-256. It checks source reads and blocks until work
has completed or failed requests have drained and cleanup has been attempted.
Concurrent callers share worker, request, buffer and file-admission limits.
Uploads larger than the configured part size use multipart requests; the
10,000-part limit allows 156.25 GiB with 16 MiB parts. Larger files require a
larger part size and compatible buffer budget. The upload buffer budget excludes
SDK/TLS overhead and restore mappings.

Requests have finite connection and total HTTP timeouts, with three retries by
default. The default two-hour upload deadline includes file admission and is
capped by a caller-supplied deadline when present. Deadline expiry starts
cancellation; blocking filesystem I/O, safe draining and cleanup can extend
return time.

Multipart initiation is attempted once because a lost response can hide the
upload ID. On failure, the client drains requests, aborts only its known upload
ID and verifies cleanup with `ListParts`, using two rounds by default. `S3Error`
retains the primary failure, remote outcome and any cleanup failure. Failed
cleanup or lost initiation responses can leave unfinished multipart uploads.
A lost PUT or completion response can mean an object exists despite an error;
the client reports uncertainty and leaves completed objects intact. Publication
reconciliation belongs to the caller. Remote retention, orphan cleanup and
store encryption policy remain deployment responsibilities.

## Direct C++ configuration

Connection settings support region, endpoint, path/virtual addressing, a custom
CA and explicit credentials or each library's AWS provider chain. Keep process
settings consistent for the lifetime of the clients. TLS verification stays
enabled, and neither the SDK client nor the engine changes the environment per
operation.

| Input | Behavior |
| --- | --- |
| `S3TransferOptions.connection.region` / `.endpoint` | Shared region and HTTP(S) endpoint for uploader and reader generations |
| `.access_key_id`, `.secret_access_key`, `.session_token` | Optional explicit credentials; omit all to use each library's AWS provider chain |
| `.use_virtual_addressing` | Must match `RUNAI_STREAMER_S3_USE_VIRTUAL_ADDRESSING`: `0` for path, `1` or unset for virtual addressing |
| `.ca_file` | Must match `AWS_CA_BUNDLE`; set both for a custom CA available in the runtime, or leave both empty for system trust |
| `S3TransferOptions.upload_limits` / `.restore_timeout` | Upload resource limits and per-restore deadline, retained across reader replacement |
| `RUNAI_STREAMER_CONCURRENCY`, `RUNAI_STREAMER_S3_MAX_INFLIGHT_MIB` | Native worker count and S3 in-flight read window |
| `RUNAI_STREAMER_S3_MAX_RETRIES`, `RUNAI_STREAMER_S3_TIMEOUT`, `RUNAI_STREAMER_S3_REQUEST_TIMEOUT_MS` | Native retry, chunk-retry deadline and low-speed request timeout settings |

The default `S3Limits` uses 16 MiB parts, 128 MiB of upload buffers, four workers
and two admitted files. Set custom CAs explicitly in both the connection and
environment. Engines requiring different process-level settings cannot share a
process.

## Integration boundary

This layer provides the upload backend, reader and configuration types.
PageBroker RPCs remain filesystem-only. Checkpoint index publication, artifact
RPC handling, configured transaction admission and daemon startup wiring arrive
in the artifact integration layer.
