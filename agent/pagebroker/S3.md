# S3 storage contract

This document describes the experimental S3 backend's startup configuration,
content/container object layout, and checkpoint/restore protocol. PageBroker
accepts the configured store ID and returns opaque publication handles. The
agent supplies artifact identities and persists the descriptors; deployment
wiring and operator maintenance are owned separately.

PageBroker uses one `Broker` transaction registry for local staging and delegates
S3 transfers to `ModelStreamerTransferEngine`. The engine owns a concrete
`S3StorageBackend(S3Config)` for storage operations and restores payloads through
the native Model Streamer. The backend owns a snapshot of the startup configuration,
object layout, upload preflight, rclone payload uploads, and index loading and
publication. The engine implements the shared transfer API for staged S3
checkpoint and restore only; filesystem storage uses the POSIX engine. It
delegates storage operations to the backend. The backend creates its S3 wrapper lazily;
both it and the native reader use the same resolved startup credentials.

`transfer/s3/checkpoint_index.*` handles the file inventory format;
`transfer/s3/s3_client.*` is the backend's private rclone wrapper for bounded requests,
upload batches, and child-process cleanup. The backend has no transaction registry
or native reader session. There is no separate artifact store or
credential-rotation manager.

The broker owns the transaction registry, retention queue, and admission pool.
Each `Transaction` owns its deadline, cancellation, and staging reservation until
cleanup succeeds. Restore prepares a local `CheckpointInventory`, reserves its size,
and passes that inventory directly to ModelStreamer. Checkpoint transactions retain
only their destination and publication state across Commit retries; the saved
index allows uncertain publication to be reconciled without reuploading payloads.
Destination ownership lasts until the retained transaction is destroyed.
Abort signals cancellation before waiting for the transaction lock, then removes
staging after active I/O drains. Reaping skips busy transactions so network work
cannot block the daemon from accepting Abort requests.

## Payload uploads and native restores

PageBroker validates incoming descriptors with `ValidateArtifactDescriptor` at
request admission. Checkpoint targets go through `ResolveTarget`. Subsequent
backend operations require a descriptor accepted by that same backend.

`S3StorageBackend::BuildCheckpointInventory` scans an immutable source directory and
validates payload keys beneath the artifact's configured store location. It
validates the complete inventory, paths, destinations, index limits and file
sizes before writing any payload, including empty files.

`PublishCheckpoint` sends the validated payload inventory to one `rclone copy`
process, then publishes the index separately after that process succeeds. Rclone
uploads one file at a time within the batch. Concurrent batches share the
wrapper's operation and multipart-buffer limits.

Callers must keep the source tree immutable until upload returns and retain
exclusive ownership of the source directory, destination prefix, and publication
state across retries. Concurrent checkpoints using the same source directory or
S3 prefix are unsupported; the uploader does not add locks or detect source
changes during a transfer.

`PrepareRestore` reads the published index and returns S3 locators, sizes,
file/directory permissions and empty directories. Direct C++ callers can use
`S3Client::UploadFiles` with a relative-path inventory and a finite cancellation
deadline.

`ModelStreamerRestore::Stage` reads payloads through the native S3 plugin.
File permissions are applied during creation, before native reads write through
their existing mappings. Directory permissions are applied after restoration,
children before parents. PageBroker checks index structure and object sizes but
does not generate or verify payload digests.
Same-size payload replacement or corruption can therefore go undetected. SDK
signing, TLS, and transport checksum behavior remain independent of these checks.

Healthy native sessions stay open between restores. Admission allows at most
eight outstanding submissions with a combined 10 GB target; an oversized file
runs alone. Successful submissions release their mappings and admission capacity
as soon as all their ranges complete. A storage error stops new admission until
existing submissions drain and the native session ends; failed mappings remain
valid through teardown. The target bounds admitted bytes, not total staging
memory, which also includes queued restore mappings.

The pinned plugin cancels and removes S3 clients process-wide on session
teardown. Only one coordinator may own a native session per process; independent
concurrent coordinators are unsupported. Requests sharing that coordinator can
run concurrently.

The engine replaces a failed restore coordinator using the same connection
settings and restore timeout. Each native session receives those credentials
before its first request. The pinned API has no per-submission cancellation or
live credential replacement. Cancelling an accepted restore stops the shared
session and can fail concurrent restores; cancelling queued work leaves active
reads running. In either case, callers return only after native access to their
buffers has stopped.

Empty files are created locally without a native download. Callers preparing
raw restore inventories must separately check remote empty-object existence. Source
keys are passed literally to the pinned URI parser, without percent-encoding;
keys containing newline characters are unsupported. S3 URIs must not be put
into filesystem protobuf fields.

## S3 client and failure handling

`S3Client` wraps the pinned, prebuilt rclone executable with `fork`/`exec`.
It supports payload batches, object HEAD, bounded metadata GET, and create-only
metadata PUT. See [the wrapper contract](transfer/s3/README.md) for credential,
resource, deadline, retry, and cleanup behavior. Checkpoint validation and index
publication policy belong to `S3StorageBackend`.

The caller's finite deadline covers admission and execution. Cancellation stops
and reaps the child before local staging can be released. Failed writes may
have completed remotely; index publication is confirmed by reading back the
saved bytes. Configure external retention and incomplete-multipart lifecycle
cleanup for abandoned uploads.

## Direct C++ configuration

Connection settings support region, endpoint, path/virtual addressing, a custom
CA and credentials resolved once at startup. Keep process
settings consistent for the lifetime of the clients. TLS verification stays
enabled, and neither the wrapper nor the engine changes the environment per
operation.

| Input | Behavior |
| --- | --- |
| `S3TransferOptions.connection.region` / `.endpoint` | Shared region and HTTP(S) endpoint for uploader and reader generations |
| `.access_key_id`, `.secret_access_key`, `.session_token` | Resolved credentials; loaded by the daemon from `AWS_SHARED_CREDENTIALS_FILE` |
| `.use_virtual_addressing` | Must match `RUNAI_STREAMER_S3_USE_VIRTUAL_ADDRESSING`: `0` for path, `1` or unset for virtual addressing |
| `.ca_file` | Must match `AWS_CA_BUNDLE`; set both for a custom CA available in the runtime, or leave both empty for system trust |
| `S3TransferOptions.upload_limits` / `.restore_timeout` | Upload resource limits and per-submission restore timeout (20 minutes by default), retained across reader replacement |
| `RUNAI_STREAMER_OBJ_CONCURRENCY`, `RUNAI_STREAMER_S3_MAX_INFLIGHT_MIB` | Native worker count and S3 in-flight read window |
| `RUNAI_STREAMER_S3_MAX_RETRIES`, `RUNAI_STREAMER_S3_TIMEOUT`, `RUNAI_STREAMER_S3_REQUEST_TIMEOUT_MS` | Native retry, chunk-retry deadline and low-speed request timeout settings |

Native restore submissions default to 20 minutes, capped by `transactionSeconds`.
The earlier transaction deadline still takes precedence during execution. This
bounds elapsed time per submission, rather than time without progress; native
teardown can extend the time before the caller returns.

`uploadTargetGbps` and `uploadWorkers` are rejected as obsolete settings.
`uploadPartBytes` must be at least 8 MiB. `uploadBufferBytes` must cover at least
one padded part per admitted operation. Round `uploadPartBytes` up to the next
whole MiB, adding one MiB when already aligned: an 8 MiB part needs 9 MiB per
operation. Each rclone process receives `uploadBufferBytes / uploadActiveFiles`
through `--max-buffer-memory`; idle buffer caches and other process memory are
additional. `uploadActiveFiles` bounds admitted operations;
a payload batch consumes one permit and uses one rclone file transfer at a time.
Set custom CAs in the shared startup configuration.

## Configuration and credentials

Start the daemon with `--storage-config /absolute/path/s3.json`. One daemon
serves either the configured S3 store or the existing filesystem backend.
A minimal production configuration is:

```json
{
  "storeId": "snapshot-store-a",
  "endpoint": "https://s3.us-east-1.amazonaws.com",
  "region": "us-east-1",
  "bucket": "checkpoint-bucket",
  "prefix": "checkpoints/installation-a"
}
```

Optional fields are `addressing` (`virtual`, the default, or `path`), `caFile`
(an absolute path to a mounted CA; the `AWS_CA_BUNDLE` fallback must also be absolute), `allowHttp` (false by default; local testing
only), and `limits`. Unknown fields and duplicate JSON members are rejected.
The configuration is bounded to 64 KiB. TLS verification is always enabled.

| Limit | Default | Allowed bounds |
| --- | --- | --- |
| `transactionSeconds` | 7200 | 1–7200 |
| `stagingBytes` | 1 TiB | 1 byte–1 TiB |
| `activeTransactions` | 8 | 1–1024; less than `--max-concurrent-requests` |
| `uploadPartBytes` | 64 MiB | 8 MiB–1 GiB |
| `uploadBufferBytes` | 1 GiB | Up to 16 GiB; at least padded part bytes × `uploadActiveFiles` (see above) |
| `uploadActiveFiles` | 2 | 1–64 admitted operations; one permit per payload batch |
| `requestSeconds` | 60 | 1–60; idle I/O timeout |
| `uploadRequestRetries` | 3 | 0–10; bounded rclone retries; see wrapper contract |
| `uploadConnectSeconds` | Smaller of 5 and `requestSeconds` | 1–`requestSeconds` |

Native Model Streamer reader tuning belongs in the separate optional
[`--model-streamer-config` JSON file](MODEL_STREAMER.md). This S3 file remains
the shared source of connection settings for the rclone uploader and native reader.
Explicit reader tuning overrides the reader defaults documented there.

Upload buffers are allocated lazily and shared across transactions. Native
reader defaults remain four connections and a 128 MiB in-flight window,
independent of rclone upload limits. The staging
budget accounts for staged files and pending restore allocations, not rclone/native/TLS
memory. A capture reserves one byte before its size is known; Commit validates
and accounts for the completed tree before any upload. The external capture
writer remains responsible for not exhausting the staging filesystem while
writing. Keep a daemon connection available for Abort.

The daemon reads only the `[default]` profile in `AWS_SHARED_CREDENTIALS_FILE`
once at startup. The bounded shared-credentials file requires `aws_access_key_id`
and `aws_secret_access_key`, with optional `aws_session_token`. Missing or invalid
files fail startup; access-key environment variables and named profiles cannot
supply or override credentials. The same snapshot goes to each rclone child's
environment and every native reader session. Credentials are absent from command
arguments, RPCs, indexes, and logs.

Credential issuance and refresh belong to the deployment owner. Replacing a
projected file does not update the running daemon; restart it to consume new
credentials. Expired temporary credentials fail operations. This implementation
does not promise uninterrupted work across credential expiry or restart.
Addressing, CA, and native transfer settings are set once before starting work.

## Destination ownership and RPCs

Use the artifact-addressed protocol introduced in PR #395. `ArtifactTarget`
contains the configured `store_id` and the PodSnapshotContent UID/container
identity. `PublishedArtifact` contains that store ID and an opaque handle. The
format version lives in the checkpoint index. The backend validates the store
before any storage I/O and validates the format when reading the index. Keep a
store ID bound to the same bucket, prefix, and endpoint throughout its lifetime.

Exactly one writer owns each target across all daemons. Distinct captures need
distinct artifact identities. The backend returns the deterministic directory handle
`artifacts/<contentUID>/containers/<containerName>`. Handles exclude the bucket and
configured prefix; callers persist them unchanged. The backend validates identity
components before constructing paths. Old hash-only handles are rejected; existing
objects are not moved or deleted, and checkpoints using that layout must be recreated.
The broker rejects duplicate live ownership and an
already published index. There is no distributed lock or safe concurrent
publication to the same target. An absent index does not authorize recapture.

The existing optional engine selector defaults to ModelStreamer for this S3
store. An explicit incompatible engine is rejected before transaction allocation.
The protobuf oneof permits only one source or target selector; the broker rejects
a missing selector. No additional S3 RPC is introduced.

| Go client operation | Result and responsibility |
| --- | --- |
| `PrepareArtifactCheckpoint(ctx, tx, target, engine)` | Returns a local capture directory. Capture once and keep it immutable until released. |
| `CommitCheckpoint(ctx, tx, storeID)` | Uploads through rclone, publishes the index last, and returns `PublishedArtifact`. Retries retain the same descriptor. |
| `StagedArtifactRestore(ctx, tx, artifact, engine)` | Returns a local checkpoint staged by ModelStreamer. |
| `GetArtifactMetadata(ctx, tx, artifact)` | Stages only `manifest.yaml` through ModelStreamer. Always release it with Abort. |
| `Commit(ctx, tx)` or `Abort(ctx, tx)` for restore | Releases local staging after consumers finish and unmount. |
| `Abort(ctx, tx)` during work | Cancels work and waits for I/O to drain before releasing staging. |

Use a fresh transaction ID per operation. After a lost staging or metadata reply,
release the known transaction with a bounded independent cleanup context. Never
release staging while a process still reads it or a mount references it. Commit
and Abort do not delete published S3 objects. Consumers must finish and unmount
within the configured transaction lifetime; staging is eligible for removal once
that lease expires.

Draining can take longer than the cancellation/deadline; buffers remain alive
until the native reader and rclone child stop using them.

## Layout and index

Within the configured bucket:

```text
<prefix>/<artifact_handle>/data/<relative-file-path>
<prefix>/<artifact_handle>/index.json
```

An index is published only after every payload upload succeeds. Payloads use
ordinary PUT/multipart upload to the exclusively owned destination. The index
uses conditional PUT (`If-None-Match: *`). No probe object or remote delete is
needed to prepare a capture. Upload permissions can therefore fail after capture.

The JSON index contains exactly `format`, `rootMode`, `directories`, and `files`:

```json
{
  "format": "snapshot.s3-checkpoint/v1",
  "rootMode": 448,
  "directories": [{"path": "empty-dir", "mode": 448}],
  "files": [{
    "path": "manifest.yaml",
    "size": 11,
    "mode": 384
  }]
}
```

Each file entry contains exactly `path`, `mode`, and `size`; directory entries
contain exactly `path` and `mode`. Modes are decimal Unix permission bits,
limited to `0777`. File and directory arrays are independently sorted by path;
parents must be listed. Only ordinary directories and regular files are
supported. Paths must be canonical relative UTF-8 paths, at most 512 bytes,
without traversal, backslashes, control characters, duplicates, or collisions.
The entire tree, destination keys, file-size/part limits, and index-size bound
are checked before payload writes. Rclone opens the listed paths under the immutable source root.

Limits: 4 MiB index, 10,000 total entries, 1 TiB total file bytes, and a required
nonempty `manifest.yaml` of at most 1 MiB. S3 multipart limits additionally
constrain each file (S3's fixed 10,000-part limit). Bounded parsing rejects excessive
nesting, duplicate JSON keys, negative/overflowing sizes, and unexpected fields.

Restore loads the bounded index once, validates it, checks each selected remote
object's size, and builds a Model Streamer restore inventory. Empty objects must exist
even though empty local files require no native download. The reader applies
permissions after native access completes. Metadata fetching uses a writable
local directory containing only the manifest.

PageBroker does not calculate or validate payload digests. Payload integrity
requires a separate design.

Equal index bytes confirm the expected publication metadata, not equal payload
contents. Publication retries still require the original immutable source, saved
index bytes, and exclusive destination ownership.

## Retry, expiry, and restart

Before index publication starts, a failed Commit can retry the same immutable
capture in the same live transaction. Earlier payloads may be overwritten. This
is safe only under the exclusive-destination contract.

Before attempting the index, the transaction saves its exact serialized bytes.
From that point, Commit retries only confirm or publish those bytes; they never
rewrite payloads. A lost PUT response is reconciled by reading and comparing the
index. An unreadable/unconfirmed index returns `OUTCOME_UNKNOWN`. Keep the target and any returned descriptor; recover without capturing the process again. A conflicting
index is an error, never permission to overwrite another publication.

Transactions have a fixed lifetime from admission; retries do not extend it.
Expiry stops new work and the periodic sweep removes capture, restore, and
metadata staging after active broker I/O drains. Failed cleanup stays retryable
and retains its staging reservation and admission slot until removal succeeds.
Commit and Abort return `TRANSACTION_EXPIRED` while an expired transaction is
remembered; the periodic sweep owns its cleanup. Once reaped, either request
returns `TRANSACTION_NOT_FOUND`. An Abort completed before expiry remains
idempotent while its terminal record is retained. Completed records without resources are bounded to 1024 and
one hour; the periodic sweep also collects records missed during request completion.

Restart starts a fresh transaction registry and discards abandoned local staging,
including read-only trees. It never resumes an interrupted operation and leaves
published objects intact. After restart, an unknown transaction requires external recovery:
use the persisted descriptor to inspect the publication and retain uncertainty
if it cannot be established. If the descriptor was never received, use metadata lookup by target. The broker
resolves the same deterministic handle, reads its published index, and stages only
the manifest. The response includes the descriptor. A missing index returns
`ARTIFACT_NOT_FOUND`; access failures remain distinct. Lookup never writes remote
objects, resumes an upload, or repeats capture. Abort releases its private staging.
Do not automatically reuse the target or recapture. Consumers must not rely on
local staging surviving a daemon restart.

Configure external retention and lifecycle cleanup for incomplete multipart
uploads, partially uploaded objects and orphan destinations. Reconciliation of
uncertain remote publications remains the caller's responsibility.

## Deployment integration

Production agent call-site migration and chart wiring are separate integration
work: mount the configuration/credentials into PageBroker, pass `--storage-config`,
and persist CommitCheckpoint descriptors for restore and metadata calls.

PageBroker's native `make test` runs unit tests. Integration coverage is supplied
separately after the runtime configuration changes.
