# Snapshot v0.2.0 - Release Notes

Snapshot v0.2.0 is the second minor release of Snapshot, spanning 127 merged PRs from 16 contributors. **PageBroker** is now part of every install: a per-node sidecar moves checkpoint and restore data, restores read straight from checkpoint storage, and the new GPU engine keeps CUDA state between operations. Restores are **checked before CRIU runs**, so an incompatible target is refused with a clear reason instead of failing partway, and each checkpoint now records what it was captured on. Published benchmarks cover 22 configurations across vLLM, SGLang and TensorRT-LLM: a restore is 8.1x to 35.9x faster than a cold start on B200 GPUs. Releases are now **signed, with SBOMs and build provenance**.

## Summary

### PageBroker: Always-On Data Path

Every checkpoint and restore now goes through PageBroker, a sidecar next to the node agent (#86, #90, #91, #251). CPU restores read the checkpoint directly from storage with no staging copy (#468); `pageBroker.restoreMode: staged` brings the copy back. The GPU engine is on by default (#369): it keeps CUDA contexts and transfer buffers between operations, overlaps GPU setup with data transfer, and runs GPU work inside storage transactions (#365, #366, #367, #368). PageBroker ships as its own image (#250) and no longer needs a kernel with `SO_PEERPIDFD` (#512).

### Safer Restores

Snapshot records the host, pod, mounts and GPU environment with each checkpoint and compares them before restore starts. An incompatible restore is refused with a stable reason on the pod's `Restored` condition, in events and in logs (#140). `PodSnapshotContent.status.source` shows what a checkpoint was captured on: node, architecture, kernel, image and digest, resource limits, driver version and GPU models (#141). A failed restore now reports the error that stopped it rather than the first one CRIU logged (#532).

### Verifiable Releases

From v0.2.0 the operator image, agent image and Helm chart are signed with keyless cosign. Each image carries SLSA provenance and an SPDX SBOM, and each release has SPDX and CycloneDX SBOMs plus a signed `SHA256SUMS` attached (#299, #303). Actions are pinned by SHA, CodeQL runs on every PR, and base images are digest-pinned (#271, #277, #284).

### Runs on More Clusters

OpenShift (SCC `anyuid`) installs work with the chart (#157, #192). RKE2 and k3s are supported through `runtime.storageDir` (#146). Clusters where NVIDIA is containerd's default runtime can set `daemonset.runtimeClassName: ""` (#497), and the operator takes `nodeSelector`, `affinity` and `tolerations` (#429).

### Benchmarks You Can Reproduce

Cold start versus restore numbers for 22 configurations are in the [benchmarks doc](https://github.com/ai-dynamo/snapshot/blob/v0.2.0/docs/development/benchmarks.md): vLLM, SGLang and TensorRT-LLM on 1 to 8 B200 GPUs, including a 913 GB model that restores in about 40 seconds. A `benchmarks/` tool reproduces them on your own hardware and models (#282), and a dashboard tracks end-to-end benchmark history (#281, #286, #387).

## Upgrade Notes

These matter when moving from v0.1.0.

- **PageBroker is always on and uses node memory.** The chart adds a PageBroker sidecar to the agent pod. It requests 8 CPUs and 32 GiB and is limited to 32 CPUs and 256 GiB by default. Checkpoints and staged restores use a RAM volume of up to 64 GiB (`pageBroker.staging.sizeLimit`), and the agent's own memory limit is 64 GiB. Check that GPU nodes have the headroom, or tune `pageBroker.resources` and `pageBroker.staging.sizeLimit` (#251, #369).
  > **Migrate:** Set both image tags together with `image.agent.tag`. A separate `image.pageBroker.tag` now fails chart rendering, because the two images ship as a pair.
- **New CRD field.** `PodSnapshotContent.status.source` is added; deploy the matching CRDs and operator together. It is filled in for checkpoints that reach `Ready` after the upgrade, and existing ones are not backfilled (#141).
- **Restores are refused when the target does not match.** Existing checkpoints missing either side of a comparison stay restorable. To bypass the checks, set the `nvidia.com/snapshot-skip-compat-check: "true"` annotation on one pod, or `config.restore.skipCompatCheck` for a whole node (#140).
- **Checkpoints that run too long now fail.** `config.checkpoint.checkpointTimeoutSeconds` defaults to 3600.
- **No more Leases.** The agent drives checkpoints from a workqueue instead of per-checkpoint `coordination.k8s.io` Leases, so the `LeaseCancelled` failure reason no longer occurs. The now-unused `leases` rule stays in the agent `ClusterRole` for one more release (#385).
- **`restore-complete` changed content.** The file in `/snapshot-control` now holds `pid=<restored PID>`, and a new `restore-failed` marker is written when a restore fails. Anything that checks only that the file exists is unaffected (#481).
  > **Migrate:** If you copied `app.py` from the guides, read `SNAPSHOT_RESTORE_STANDBY`. The deprecated `DYN_SNAPSHOT_RESTORE_STANDBY` name is removed from the repository (#170).
- **Chart image tags.** The chart's `appVersion` now matches the published tag format (`v0.1.0`), so the default operator and agent images resolve (#431).

## Features & Improvements

### Checkpoint & Restore

- Restore GPU workloads onto a different physical `/dev/nvidiaN` than they were captured on. Snapshot records the UUID-to-device-path mapping with each checkpoint, and this needs a fresh checkpoint (#306, #380).
- Clone restores rewrite every bound abstract UNIX socket, so a second clone on the same node no longer collides with the first on NCCL sockets (#167).
- Checkpoint storage gains integrity-checked manifests and a transfer-neutral `CustomStorage` helper (#109, #300).

### Operator & Chart

- An in-process maintenance workqueue cleans up checkpoint artifacts on PVC storage, with panic recovery and a per-item timeout (#349, #390).
- The chart package includes the license (#485).

### Groundwork For What Comes Next

These are in the tree but not yet user-facing.
- **S3 checkpoint storage:** the operator has an S3 maintenance backend, and the design is in SNEP-237 (#392, #344). `storage.type` still supports only `pvc` in this release.
- **cuInterpose:** a CUDA interposition layer for tracking shared GPU memory across processes (#326, #327, #328, #329, #330, #331, #332, #333, #342, #360).
- **Snapshot-owned PID 1 in restored containers:** the `snapshot-restore-proxy` binary ships in the agent image, but nothing runs it yet (#490).

## Bug Fixes

- Fixed a failed restore reporting a misleading error: the pod condition and events now carry the real cause for each destination (#532).
- Fixed PageBroker GPU checkpoints on kernels without `SO_PEERPIDFD` (#512).
- Fixed PageBroker `CustomStorage` on shared filesystems such as SMB that report group- or world-writable directory modes. GPU artifacts are still created owner-only (#516).
- Fixed restore failing, or silently using the application image's own `tar`, when the workload image ships an older glibc than the agent's (#467).
- Kept the agent building with containerd 2.3.5 by pinning `genproto` above the googleapis/rpc split (#316).
- Updated Go dependencies flagged by the dependency scan and `containerd/v2` to v2.3.6 for GO-2026-6597 (#403, #439), and built with Go 1.27.2 (#529).

## Testing & CI

- End-to-end checkpoint/restore tests cover the vLLM, SGLang and TensorRT-LLM guide workloads (#175, #176), and a CPU-only e2e suite runs without GPUs (#445, #476, #487).
- Upgrade tests restore snapshots taken by earlier releases, nightly and weekly against the last three (#418, #419, #420, #479).

## Documentation

- **New:** the [workload contract](https://github.com/ai-dynamo/snapshot/blob/v0.2.0/docs/reference/workload-contract.md) states what a workload must do to be checkpointed and restored, so building a custom image is one way to meet it rather than a requirement (#279). Also new: the restore pod contract reference (#159), the SNEP proposal process (#253), and the Snapshot alpha docs and usage guides (#132).
- **Install and operations:** OpenShift installation (#192), a verification path for TensorRT-LLM without a GPU driver (#224), and Datadog GPU monitoring as a known limitation (#168).
- **Project:** code of conduct, governance, maintainers and contribution policy (#256, #277, #298), the release process (#260), and a changelog (#298). Every PR now needs a link to an approved issue (#254).

## Known Issues

- Linux nodes only, x86_64 or arm64.
- Single-node workloads only; multi-node is on the roadmap.
- vGPU is not supported.
- The checkpointed workload must not run tools that intercept `libcuda.so` calls, such as Datadog GPU monitoring. CUDA calls can fail or hang after restore.
- Restoring onto a different physical `/dev/nvidiaN` needs a checkpoint taken with this release or later. Older checkpoints keep their previous behavior.
