# Snapshot v0.2.0 - Release Notes

Snapshot v0.2.0 is the second minor release of Snapshot, spanning 139 merged PRs from 16 contributors. **Multi-GPU support** is the headline: a single-node workload can now span up to 8 GPUs, and its CUDA graphs replay after restore without recapture. Snapshot also runs on **arm64 nodes**, restores read straight from the snapshot store through **PageBroker**, an incompatible restore is **refused before CRIU runs**, and releases are **signed with SBOMs and build provenance**. Across 22 benchmarked configurations on B200 GPUs, a restore is 8.1x to 35.9x faster than a cold start, and a 913 GB model on 8 GPUs restores in about 40 seconds instead of 15 minutes.

## Summary

### Multi-GPU: Single-Node Checkpoint & Restore

Snapshot adds opt-in multi-GPU support (Beta) for workloads whose processes share CUDA memory across the GPUs of one node. It preserves each process's pointers, the memory contents and the sharing relationships between processes, including multicast mappings, so existing CUDA graphs replay after restore without recapture (#326, #327, #328, #329, #330, #331, #332, #333, #342, #360). Enable it with the `nvidia.com/snapshot-multi-gpu: "enabled"` annotation on the source Pod (#336, #626). SnapshotJob does the rest: it adds the launcher and prefixes the target container's `command`. Peer-accessed allocations are carried through checkpoint and restore (#551, #558), and a restore onto a different physical `/dev/nvidiaN` is remapped (#306, #380). The benchmarks cover 13 multi-GPU configurations with vLLM, SGLang and TensorRT-LLM on 2, 4 and 8 GPUs. See the [multi-GPU design](https://github.com/ai-dynamo/snapshot/blob/main/docs/reference/architecture/multi-gpu.md) and the [usage guides](https://github.com/ai-dynamo/snapshot/blob/main/docs/guides/README.md).

### Arm64: Native Images & Node Support

The node agent, PageBroker and operator images are built for `linux/arm64` as well as `linux/amd64`, and the chart schedules the node agent on arm64 nodes (#535). Release images are published as multi-architecture indexes, with SBOMs for both architectures. The vLLM guide pins the multi-architecture digest, so the same manifest pulls the right image on either architecture. Validated on NVIDIA GB300 with vLLM and SGLang.

### Restore Speed: PageBroker Direct Restore & GPU Engine

Every time Snapshot takes or restores a snapshot, the work now goes through PageBroker, the node agent's sidecar (#86, #90, #91, #251). A restore reads the snapshot straight from the snapshot store with no staging copy (#468); `pageBroker.restoreMode: staged` brings the copy back. The GPU engine is on by default (#369): it keeps CUDA contexts and transfer buffers between operations, overlaps GPU setup with data transfer, and runs GPU work inside storage transactions (#365, #366, #367, #368). PageBroker ships as its own image (#250) and works on kernels without `SO_PEERPIDFD` (#512).

### Restore Safety: Compatibility Checks & Clear Errors

Snapshot records the host, Pod, mounts and GPU environment with each snapshot and compares them before a restore starts. An incompatible restore is refused with a stable reason on the Pod's `nvidia.com/Restored` condition, in events and in logs (#140). `PodSnapshotContent.status.source` shows what a snapshot was taken from: node, architecture, kernel, image and digest, resource limits, driver version and GPU models (#141). A failed restore now reports the error that stopped it rather than the first one CRIU logged (#532).

### Supply Chain: Signed Releases, SBOMs & Provenance

From v0.2.0 the operator image, node agent image and Helm chart are signed with keyless cosign. Each image carries SLSA provenance and an SPDX SBOM, and every release attaches SPDX and CycloneDX SBOMs plus a signed `SHA256SUMS` (#299, #303). Actions are pinned by SHA, CodeQL runs on every PR, and base images are digest-pinned (#271, #277, #284).

### Platforms: OpenShift, RKE2 & k3s

The chart installs on OpenShift under the `anyuid` SCC (#157, #192) and on RKE2 and k3s through `runtime.storageDir` (#146). Clusters where NVIDIA is containerd's default runtime can set `daemonset.runtimeClassName: ""` (#497), and the operator takes `nodeSelector`, `affinity` and `tolerations` (#429).

## Upgrade Notes

These matter when moving from v0.1.0.

- **PageBroker is always on and uses node memory.** The chart adds a PageBroker sidecar to the node agent Pod. It requests 8 CPUs and 32 GiB and is limited to 32 CPUs and 256 GiB by default. Taking a snapshot and staged restores use a RAM volume of up to 64 GiB (`pageBroker.staging.sizeLimit`), and the node agent's own memory limit is 64 GiB (#251, #369).
  > **Migrate:** Check that GPU nodes have the headroom, or tune `pageBroker.resources` and `pageBroker.staging.sizeLimit`. Set both image tags with `image.agent.tag`; a separate `image.pageBroker.tag` now fails chart rendering, because the two images ship as a pair.
- **Restores are refused when the destination does not match.** A snapshot that is missing either side of a comparison stays restorable (#140).
  > **Migrate:** To bypass the checks, set the `nvidia.com/snapshot-skip-compat-check: "true"` annotation on one Pod, or `config.restore.skipCompatCheck` for a whole node.
- **New CRD field.** `PodSnapshotContent.status.source` is added; deploy the matching CRDs and operator together. It is filled in for snapshots that reach `Ready` after the upgrade, and existing ones are not backfilled (#141).
- **Taking a snapshot now fails once it outruns `config.checkpoint.checkpointTimeoutSeconds`.** The default is 3600 seconds.
- **No more Leases.** The node agent drives each checkpoint from a workqueue instead of `coordination.k8s.io` Leases, so the `LeaseCancelled` failure reason no longer occurs. The now-unused `leases` rule stays in the node agent `ClusterRole` for one more release (#385).
- **`restore-complete` changed content.** The file in `/snapshot-control` now holds `pid=<restored PID>`, and a `restore-failed` marker is written when a restore fails. Anything that only checks that the file exists is unaffected (#481).
  > **Migrate:** If you copied `app.py` from the guides, read `SNAPSHOT_RESTORE_STANDBY`. The deprecated `DYN_SNAPSHOT_RESTORE_STANDBY` name is removed from the repository (#170).
- **Multi-GPU annotation key.** If you tried multi-GPU on a release candidate, rename `nvidia.com/cuda-shared-memory-support` to `nvidia.com/snapshot-multi-gpu`. The old key is not kept as an alias (#626).
- **Chart image tags.** The chart's `appVersion` now matches the published tag format (`v0.1.0`), so the default operator and node agent images resolve (#431).

## Features & Improvements

### Multi-GPU

- **Opt-In Annotation:** Added `nvidia.com/snapshot-multi-gpu`, validated by SnapshotJob admission and by the node agent for Pods you create yourself. `enabled` turns it on; `disabled` or no annotation leaves it off (#336, #626).
- **Launcher Delivery:** SnapshotJob adds an init container that copies the launcher and libraries from the node agent image and prepends the launcher to the target container's `command`. For a Pod you create yourself, prefix `command` with the launcher (#336).
- **Shared Memory Preserved:** Tracked CUDA memory shared through legacy IPC and VMM APIs, including unicast and multicast mappings, and saved each shared allocation once rather than once per process (#329, #330, #331, #342).
- **Group Coordination:** Added a coordinator that prepares and restores all participating processes together and verifies the restored state before the workload resumes (#332).
- **Device Remapping:** Restored UUID-mapped legacy GPU device paths onto a different physical `/dev/nvidiaN`, and kept native GPU device mounts across CRIU restore. This needs a fresh snapshot (#306, #380).
- **Peer GPU Access:** Preserved allocations that other GPUs can access even when they were never exported (#551, #558), and identified CUDA libraries by link map instead of load address (#629).
- **Compatibility Checks:** Refuse a restore onto a different GPU count, GPU model or driver (#140).

### Arm64

- **Multi-Architecture Images:** Built the node agent and PageBroker images for both architectures, with per-architecture loader, Rust target and package baseline (#535).
- **Chart Scheduling:** The node agent DaemonSet can now schedule on `arm64` nodes (#535).

### PageBroker & Restore Speed

- **Direct CPU Restore:** Restored from the snapshot store without copying into staging; `pageBroker.restoreMode: staged` opts back in (#468).
- **GPU Engine:** Embedded a GPU engine in PageBroker with an artifact format, shared transfer rings and storage transactions, on by default with 32 slots of 128 MiB per visible GPU (#423, #365, #366, #367, #369).
- **Packaging:** PageBroker has its own image, bundled GPU dependency sources and notices, and no longer needs `SO_PEERPIDFD` (#250, #465, #512).
- **Integrity-Checked Manifests:** Added integrity-checked storage manifests and a transfer-neutral storage helper (#109, #300).

### Restore Safety

- **Compatibility Gates:** Compared host, Pod, mount and GPU environment before CRIU runs, with a per-Pod and a per-node bypass (#140).
- **Source Record:** Published `status.source` on `PodSnapshotContent` (#141).
- **Failure Reporting:** Reported the last real CRIU error per destination container, as `<destination>: <cause>` on the `nvidia.com/Restored` condition (#532).
- **Restore Markers:** Wrote the restored PID and a `restore-failed` marker to `/snapshot-control` (#481).

### Operator & Chart

- **Snapshot Store Cleanup:** An in-process maintenance workqueue cleans up snapshot artifacts on PVC storage, with panic recovery and a per-item timeout (#349, #390).
- **Checkpoint Workqueue:** The node agent drives each checkpoint from one workqueue, which removed about 450 lines and the Lease handling (#385).
- **Chart Values:** Added `runtime.storageDir`, `daemonset.runtimeClassName` and operator scheduling controls; the chart package includes the license (#146, #497, #429, #485).

### Benchmarks

- **Published Results:** 22 configurations across vLLM, SGLang and TensorRT-LLM on 1 to 8 B200 GPUs, in the [benchmarks doc](https://github.com/ai-dynamo/snapshot/blob/main/docs/development/benchmarks.md).
- **Reproduce Them:** Added a `benchmarks/` tool that runs the cold start, checkpoint and restore cycle on your own hardware and models (#282), and a dashboard for end-to-end benchmark history (#281, #286, #387).

## Bug Fixes

- **Clone Restores:** Rewrote every bound abstract UNIX socket on clone restore, so a second clone on the same node no longer collides with the first on NCCL sockets (#167).
- **Restore Errors:** Fixed a failed restore reporting a misleading error (#532).
- **Older Workload Images:** Fixed restore failing, or silently using the application image's own `tar`, when the workload image ships an older glibc than the node agent's (#467).
- **Shared Filesystems:** Fixed PageBroker on filesystems such as SMB that report group- or world-writable directory modes. GPU artifacts are still created owner-only (#516).
- **Operator Memory:** Raised the operator memory limit to 256Mi, because the manager could be OOMKilled at 128Mi (#620).
- **Build and Dependencies:** Kept the node agent building with containerd 2.3.5 (#316), updated Go dependencies flagged by the dependency scan and `containerd/v2` to v2.3.6 for GO-2026-6597 (#403, #439), and built with Go 1.27.2 (#529).

## Testing & CI

- End-to-end checkpoint and restore tests cover the vLLM, SGLang and TensorRT-LLM guide workloads (#175, #176), and a CPU-only e2e suite runs without GPUs and is about twice as fast as before (#445, #476, #487, #533, #617).
- Upgrade tests restore snapshots taken by earlier releases, nightly and weekly against the last three (#418, #419, #420, #479).

## Known Issues

### Backend (TensorRT-LLM)

#### Arm64 Checkpoint Hangs With the Default MPI Worker

On arm64 nodes, a TensorRT-LLM workload that uses the guide's default MPI worker hangs while Snapshot checkpoints it, because the worker does not answer CUDA checkpoint requests. The cause is unknown. **Workaround:** set `TLLM_WORKER_USE_SINGLE_PROCESS=1` on the workload.
