# Snapshot v0.3.0 - Release Notes

> **Draft.** v0.3.0 is not released yet. This covers what has merged to `main` since v0.2.0, as of 2026-11-01 (`6a3b4f3`), and will change until the release is cut.

Snapshot v0.3.0 is the third minor release of Snapshot, spanning 67 merged PRs from 14 contributors. **S3 snapshot storage** is the headline: Snapshot can now keep snapshots in an S3-compatible bucket, so a cluster no longer needs a shared `ReadWriteMany` volume. Restored containers now **end when the restored workload ends**, with its exit code, and restores run on nodes with and without the new runtime support. Failures are **named by the step they came from**, a transient commit failure no longer throws away a finished checkpoint, and a checkpoint a node cannot stage is refused before the workload is touched. Restores are also checked against **MIG slices, CPU instruction sets and AppArmor or SELinux labels** before CRIU runs.

## Summary

### S3: Snapshot Storage Without a Shared Volume

Snapshot now stores snapshots in any S3-compatible object store. Set `storage.type: s3` and point `storage.s3` at an endpoint, region, bucket and prefix, with credentials from a Secret (`storage.s3.credentialsSecretRef`). PageBroker uploads the files of each snapshot through rclone and publishes an index of them, and a restore validates that index and downloads the files into staging with Model Streamer ([#258](https://github.com/ai-dynamo/snapshot/pull/258), [#410](https://github.com/ai-dynamo/snapshot/pull/410), [#416](https://github.com/ai-dynamo/snapshot/pull/416), [#469](https://github.com/ai-dynamo/snapshot/pull/469)). The operator and chart resolve the store, bind every new snapshot to it, and clean up its artifacts ([#471](https://github.com/ai-dynamo/snapshot/pull/471), [#492](https://github.com/ai-dynamo/snapshot/pull/492), [#663](https://github.com/ai-dynamo/snapshot/pull/663), [#474](https://github.com/ai-dynamo/snapshot/pull/474)). Path-style addressing, a private CA bundle, plain-HTTP test endpoints and transfer limits are chart values ([#694](https://github.com/ai-dynamo/snapshot/pull/694)). A PVC remains the default. See [Storage](https://github.com/ai-dynamo/snapshot/blob/main/docs/operations/storage.md#other-backends).

### Restore Containers That End With the Workload

Every restored container now runs Snapshot's restore proxy as PID 1. It waits for the restore, forwards signals to the restored process, and exits with that process's exit code, so the container ends when the restored workload does ([#504](https://github.com/ai-dynamo/snapshot/pull/504), [#537](https://github.com/ai-dynamo/snapshot/pull/537)). The proxy needs NRI v0.10 or newer, which means containerd 2.2 or newer. On older runtimes the node agent restores without it, as before ([#633](https://github.com/ai-dynamo/snapshot/pull/633)).

### Reliability: Named Failures, Kept Work & Early Refusals

A failed checkpoint or restore now says which step it came from, as `while <step>: <cause>`, including the steps inside `nsrestore`, and the troubleshooting guide has one entry per step ([#587](https://github.com/ai-dynamo/snapshot/pull/587), [#690](https://github.com/ai-dynamo/snapshot/pull/690), [#588](https://github.com/ai-dynamo/snapshot/pull/588)). A failed dump records why, and says whether another attempt could help ([#685](https://github.com/ai-dynamo/snapshot/pull/685)). A transient commit failure no longer destroys a finished checkpoint ([#642](https://github.com/ai-dynamo/snapshot/pull/642)), and a checkpoint the node cannot stage is refused before the workload is suspended ([#687](https://github.com/ai-dynamo/snapshot/pull/687)). A panic while handling one work item no longer takes the node agent down ([#641](https://github.com/ai-dynamo/snapshot/pull/641)).

### Restore Safety: MIG, CPU Features & Security Labels

A checkpoint or restore on a MIG slice is refused up front, under the new `mig-slice` check, because Snapshot supports whole GPUs only ([#318](https://github.com/ai-dynamo/snapshot/pull/318)). A restore onto a node whose CPU lacks an instruction set the source CPU offered, such as AVX-512 or SVE2, is refused under the new `cpu-features` check instead of restoring a process that dies with `SIGILL` ([#545](https://github.com/ai-dynamo/snapshot/pull/545), [#546](https://github.com/ai-dynamo/snapshot/pull/546), [#547](https://github.com/ai-dynamo/snapshot/pull/547)). Restores into containers with an AppArmor profile or SELinux label now pass the label to CRIU ([#607](https://github.com/ai-dynamo/snapshot/pull/607)).

### Restore Speed

PageBroker prepares the participants that have GPU data first, so GPU setup overlaps the transfer ([#672](https://github.com/ai-dynamo/snapshot/pull/672)). The node agent extracts the root filesystem diff with parallel read-ahead instead of a staging copy ([#724](https://github.com/ai-dynamo/snapshot/pull/724)), and checks security labels from a recorded value instead of scanning every CRIU image on each restore ([#708](https://github.com/ai-dynamo/snapshot/pull/708)). S3 restores skip the per-file existence checks ([#728](https://github.com/ai-dynamo/snapshot/pull/728)).

## Upgrade Notes

These matter when moving from v0.2.0.

- **Restore containers run the restore proxy.** Snapshot replaces the command of every restore destination container with `/snapshot-control/snapshot-restore-proxy`. The node agent sets it through NRI when the container is created, and fails the restore if the proxy is not PID 1. Restore Pods on nodes with the proxy keep the source's command, which never runs, and are expected to use `restartPolicy: Never`: a restored container that starts again ends in `CrashLoopBackOff`. The node agent mounts the runtime's NRI socket directory, `/var/run/nri` ([#504](https://github.com/ai-dynamo/snapshot/pull/504), [#537](https://github.com/ai-dynamo/snapshot/pull/537), [#633](https://github.com/ai-dynamo/snapshot/pull/633)).
  > **Migrate:** Set `restartPolicy: Never` on restore Pods. Where clusters share nodes, such as vCluster tenants, set `daemonset.nriHostNamespace` so each installation uses its own NRI namespace. On nodes without NRI v0.10 or newer, restore Pods still need an inert command. `SNAPSHOT_RESTORE_STANDBY` is deprecated and the `DYN_SNAPSHOT_RESTORE_STANDBY` alias is removed in the next release.
- **Failure messages changed.** They open with the step they came from, as `while <step>: <cause>`, on the Pod's `nvidia.com/Restored` condition, the `PodSnapshotContent` `Failed` condition, the restore events and the node agent log. The log also carries a structured `step` key ([#587](https://github.com/ai-dynamo/snapshot/pull/587), [#690](https://github.com/ai-dynamo/snapshot/pull/690)).
  > **Migrate:** Update alerts and log filters that match the previous wrap text.
- **Restoring into an AppArmor or SELinux container needs labels in the snapshot.** A restore without them is refused up front under the new `lsm-labels` check, which `nvidia.com/snapshot-skip-compat-check` does not waive. Snapshots taken by earlier node agent versions on AppArmor nodes do not have the labels ([#607](https://github.com/ai-dynamo/snapshot/pull/607), [#708](https://github.com/ai-dynamo/snapshot/pull/708)).
  > **Migrate:** Take those snapshots again.
- **New refusals.** A restore onto a CPU missing an instruction set is refused under `cpu-features`. A snapshot taken before the upgrade recorded no CPU flags and is not checked ([#545](https://github.com/ai-dynamo/snapshot/pull/545), [#546](https://github.com/ai-dynamo/snapshot/pull/546), [#547](https://github.com/ai-dynamo/snapshot/pull/547)). A checkpoint or restore on a MIG slice is refused under `mig-slice`. A checkpoint fails before anything is locked, leaving the source process running, and `nvidia.com/snapshot-skip-compat-check` waives the restore side ([#318](https://github.com/ai-dynamo/snapshot/pull/318)).
- **New CRD fields.** `PodSnapshotContent` gains `spec.storage.storeID` and `status.storage.artifacts`, and `SnapshotJob` gains `spec.nonTargetArtifacts`. Deploy the matching CRDs and operator together ([#471](https://github.com/ai-dynamo/snapshot/pull/471), [#489](https://github.com/ai-dynamo/snapshot/pull/489)).
- **Failed non-target output is kept unless you opt in.** Omitting `SnapshotJob.spec.nonTargetArtifacts`, or setting `Retain`, preserves what non-target containers wrote to a shared volume. The old writer annotation is still accepted but no longer grants automatic cleanup ([#489](https://github.com/ai-dynamo/snapshot/pull/489)).
  > **Migrate:** To clean up after a failed job, declare the writers and set `onFailure: Cleanup` in `spec.nonTargetArtifacts`.
- **PageBroker staging is capped below the node agent's memory limit.** The default staging volume is now 56Gi against the 64Gi limit, so staging can no longer push the node agent into an OOM kill. A cap that leaves no room is lowered to the limit less 8Gi instead of failing the install ([#640](https://github.com/ai-dynamo/snapshot/pull/640)).
- **Using S3 needs matching images and one more value.** The S3 backend is in the node agent and PageBroker images of this release, not v0.2.0, so use the chart, node agent and PageBroker images from the same release. `storage.type: s3` requires `operator.bindNewContents: true`; the chart fails the render without it. PVC installs are unchanged ([#663](https://github.com/ai-dynamo/snapshot/pull/663)).

## Features & Improvements

### S3 Storage

- **S3 Store Configuration:** Added `storage.type: s3` with `storage.s3.endpoint`, `region`, `bucket` and `prefix`, and credentials from a shared-credentials-file Secret through `storage.s3.credentialsSecretRef`. The chart no longer assumes a PVC when S3 is selected ([#663](https://github.com/ai-dynamo/snapshot/pull/663)).
- **Connection Settings:** Added `storage.s3.addressing` (`path` or `virtual`), `storage.s3.allowHttp`, a CA bundle through `storage.s3.caBundleConfigMapRef`, `pageBroker.s3.limits` and `pageBroker.transferEngine.modelStreamer`. Changing one restarts PageBroker on each node ([#694](https://github.com/ai-dynamo/snapshot/pull/694)).
- **Upload and Restore Engines:** Added batch uploads through rclone and a native S3 restore engine on Model Streamer, with concurrent restores, cancellation and recovery after a failed session ([#258](https://github.com/ai-dynamo/snapshot/pull/258), [#410](https://github.com/ai-dynamo/snapshot/pull/410)).
- **Published Index:** Published an index of each snapshot's files, paths, sizes and permissions, retried an uncertain publication without uploading again, and validated the index and object sizes before restoring ([#416](https://github.com/ai-dynamo/snapshot/pull/416)).
- **Store Binding:** Bound every new snapshot to its store with `spec.storage.storeID`, recorded published artifacts in `status.storage.artifacts`, and refused to restore or clean up against a different store ([#471](https://github.com/ai-dynamo/snapshot/pull/471), [#475](https://github.com/ai-dynamo/snapshot/pull/475), [#492](https://github.com/ai-dynamo/snapshot/pull/492)).
- **Safe Cleanup:** Added a coordination contract so two cleanup operations never touch the same artifact at once, and wired PVC maintenance to it ([#474](https://github.com/ai-dynamo/snapshot/pull/474)).
- **Staging Path:** Fixed S3 restores being refused because PageBroker staged them under a different directory than the node agent accepts ([#723](https://github.com/ai-dynamo/snapshot/pull/723)).
- **Faster Restore Preparation:** Skipped per-file existence and size requests before an S3 restore. A missing or short object now fails during download with `STORAGE_ERROR` ([#728](https://github.com/ai-dynamo/snapshot/pull/728)).

### Restore

- **Restore Proxy:** Added the proxy as PID 1 in restore containers, with a fallback for runtimes without NRI v0.10 ([#504](https://github.com/ai-dynamo/snapshot/pull/504), [#537](https://github.com/ai-dynamo/snapshot/pull/537), [#633](https://github.com/ai-dynamo/snapshot/pull/633)).
- **Security Labels:** Passed the restore container's AppArmor profile or SELinux label to CRIU, and mounted the node's securityfs read-only into the node agent so CRIU can detect AppArmor ([#607](https://github.com/ai-dynamo/snapshot/pull/607)).
- **Root Filesystem Diff:** Kept files that the dumped processes held open when a rootfs exclusion matched them, so regenerable caches can be excluded safely, and extracted the diff with parallel read-ahead ([#602](https://github.com/ai-dynamo/snapshot/pull/602), [#724](https://github.com/ai-dynamo/snapshot/pull/724)).
- **Restore Ordering:** Prepared restore participants with GPU data first ([#672](https://github.com/ai-dynamo/snapshot/pull/672)).

### Compatibility Checks

- **MIG Slices:** Refused a checkpoint or restore on a MIG slice, naming the slice on the `PodSnapshotContent` `Failed` condition ([#318](https://github.com/ai-dynamo/snapshot/pull/318)).
- **CPU Features:** Recorded the source CPU's instruction sets on each snapshot and refused a restore onto a CPU that lacks one ([#545](https://github.com/ai-dynamo/snapshot/pull/545), [#546](https://github.com/ai-dynamo/snapshot/pull/546), [#547](https://github.com/ai-dynamo/snapshot/pull/547)).

### Failure Handling

- **Step Names:** Named the step a checkpoint or restore failure came from, including the steps inside `nsrestore` ([#587](https://github.com/ai-dynamo/snapshot/pull/587), [#690](https://github.com/ai-dynamo/snapshot/pull/690)).
- **Dump Failure Reasons:** Gave a failed dump a reason that tells a node momentarily out of staging (`StagingUnavailable`) from a request that will never be accepted (`BrokerRejected`), plus `StagedDataLost` and `CheckpointTimeout` ([#685](https://github.com/ai-dynamo/snapshot/pull/685)).
- **Kept Checkpoints:** Kept the staged data after a completed dump for a commit failure that may still clear, instead of releasing it ([#642](https://github.com/ai-dynamo/snapshot/pull/642)).
- **Oversized Checkpoints:** Refused a checkpoint the node cannot stage before suspending the workload, as `ImageTooLarge` with the shortfall ([#687](https://github.com/ai-dynamo/snapshot/pull/687)).
- **Resilience:** Recovered from a panic in one work item ([#641](https://github.com/ai-dynamo/snapshot/pull/641)), and let PageBroker skip a GPU that fails setup instead of exiting and stopping every operation on the node ([#714](https://github.com/ai-dynamo/snapshot/pull/714)).

### Groundwork For What Comes Next

These are in the tree but not yet user-facing.
- **Application contracts (SNEP-411):** the proposal landed ([#437](https://github.com/ai-dynamo/snapshot/pull/437)), and the first API change adds per-container settings for a checkpoint readiness probe and a post-restore action. The operator rejects them until the node agent supports them ([#734](https://github.com/ai-dynamo/snapshot/pull/734)).
- **Retrying a failed checkpoint (SNEP-394):** a configurable retry limit and failure reasons that mark which failures are retryable ([#684](https://github.com/ai-dynamo/snapshot/pull/684), [#682](https://github.com/ai-dynamo/snapshot/pull/682)). The retry itself follows.

## Bug Fixes

- **Missing Snapshots:** A restore of a `Ready` snapshot whose artifact is missing now fails with `RestoreFailed` instead of retrying forever and leaving the restore Pod and its GPU blocked ([#674](https://github.com/ai-dynamo/snapshot/pull/674)).
- **Out-of-Memory Kills:** Capped PageBroker staging below the node agent's memory limit ([#640](https://github.com/ai-dynamo/snapshot/pull/640)).
- **Multi-GPU:** Kept `cudaMalloc` semantics for converted allocations ([#673](https://github.com/ai-dynamo/snapshot/pull/673)).
- **Restore Start:** Started restores when NRI reports the destination container ([#704](https://github.com/ai-dynamo/snapshot/pull/704)).
- **Builds:** Fetched PageBroker dependency sources in the install layer ([#681](https://github.com/ai-dynamo/snapshot/pull/681)) and updated the Go toolchain to 1.27.3 ([#668](https://github.com/ai-dynamo/snapshot/pull/668)).
